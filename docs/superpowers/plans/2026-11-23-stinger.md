# Stinger Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Subir transiciones (stingers) propias, elegir una y lanzarla a voluntad; el cambio de cámara ocurre en el segundo que el usuario marca en cada video.

**Architecture:** El estado vive en el reducer del servidor (`stingers`, `stingerSelected`, `stingerRun`). Al lanzar, `/program` reproduce el video y, al llegar a `cutAt`, pide `STINGER_CUT_NOW` (el servidor hace un TAKE de corte). Un seguro en el servidor corta solo si `/program` no responde. El panel agrega la pestaña Mezclador (lista + editor de corte) y un botón TRANSICIÓN.

**Tech Stack:** Node 20 (ESM, sin dependencias nuevas), `node:test`, `linkedom` para pruebas de DOM, JS plano en navegador.

**Spec:** `docs/superpowers/specs/2026-11-23-stinger-design.md`

## Global Constraints
- Los módulos que se prueban en Node usan imports **relativos**; los de solo navegador pueden usar `/ruta` absoluta.
- Pruebas primero (TDD) → implementar → `npm test` en verde → un commit por tarea. Mensajes de commit terminan con `Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com>`.
- **Nunca borrar `data/split.json`**; para probar con persistencia usar `SPLIT_FILE=<temporal>`. Datos viejos sin los campos nuevos deben cargar sin error.
- No tocar el diseño existente salvo: botón TRANSICIÓN junto a CUT/FADE y la pestaña Mezclador (`#trans-panel`).
- No matar procesos por patrón; no tocar el servidor ni el Stream Station del usuario.
- Formatos: WebM con transparencia (VP8/VP9 alfa) es lo que lee OBS; `.mp4` solo sin transparencia; se avisa en la interfaz. Textos de interfaz en español.
- Actualmente 301 pruebas pasan; nunca bajar de eso.

## Review Focus
- Lanzar sin transición elegida, o con Preview == Program: no pasa nada (sin run, sin error).
- `STINGER_CUT_NOW` repetido o con `seq` viejo (OBS recarga, doble aviso del seguro y de `/program`): un solo corte.
- Se borra del disco el archivo de una transición registrada: se quita de la lista y deja de estar elegida.
- Lanzar dos veces seguidas: la segunda reinicia el run (no se bloquea el sistema).
- `cutAt` inválido (negativo, NaN, texto) o mayor que la duración del video: se rechaza / el corte ocurre al final del video (`ended`) en vez de no ocurrir nunca.

### Task 4: Reproductor del stinger en `/program`

**Files:**
- Create: `public/program/stinger.js`, `tests/stingerplayer.test.js`
- Modify: `public/program/program.js`, `public/program/index.html` (contenedor `<div id="stinger">` entre `#stage` y `#gfx`, `position:absolute; inset:0; pointer-events:none; z-index` mayor que la escena y menor que los GC), `public/graphics/graphics.css` solo si hace falta orden de capas.

**Interfaces:**
- Consumes: `shouldCut` de `public/shared/stinger.js` (import relativo en el módulo).
- Produces: `createStingerPlayer({ video: HTMLVideoElement-like, send(action): void }): { onState(state): void, onFrame(): void, onEnded(): void }`.
  - `onState`: si `state.stingerSelected` cambió → `video.src = '/vtr/' + encodeURIComponent(file)`, `preload='auto'` (precarga oculta, `hidden`). Si aparece un `stingerRun` con `seq` distinto del último visto → `video.currentTime = 0`, quita `hidden`, `video.play()`, `sent = false`.
  - `onFrame` (lo llama `requestVideoFrameCallback`, con respaldo `timeupdate`): si `shouldCut({currentTime, cutAt, sent})` → `send({type:'STINGER_CUT_NOW', seq})` una sola vez.
  - `onEnded`: si no se envió el corte, lo envía primero (cutAt mayor que la duración); luego `send({type:'STINGER_END', seq})` y pone `hidden`.
  - El video **no** va mudo (el audio sale por `/program`); `playsInline`.

- [ ] **Step 2:** correr → FALLA.
